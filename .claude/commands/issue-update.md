# 이슈 업데이트

현재 브랜치의 변경사항을 분석하여 연결된 이슈 본문을 실제 개발 내용으로 업데이트한다.

## 실행 순서

### 1단계: 컨텍스트 수집

아래를 병렬로 실행한다:

```bash
git branch --show-current
git diff staging..HEAD --stat
git diff staging..HEAD
```

### 2단계: 이슈 번호 파싱

브랜치명 `{type}/{number}-{suffix}` 에서 이슈 번호를 추출한다.
추출 실패 시 사용자에게 질문한다.

### 3단계: 업데이트 내용 작성

변경사항을 분석하여 아래 템플릿을 채운다:

```
## 개요
{기존 개요 유지}

## 개발 내용
- {실제 변경한 것 1}
- {실제 변경한 것 2}

## 관련 파일
- `경로/파일명` — 무엇을 바꿨는지

## 검증 방법
- [ ] {확인 항목 1}
- [ ] {확인 항목 2}
```

추론한 내용만 쓴다. 확실하지 않은 것은 빈칸으로 남긴다.

### 4단계: 확인 후 업데이트

작성한 내용을 보여주고 확인을 받는다. 확인 후 실행한다:

```bash
gh issue edit <issue-number> --body "<업데이트된 본문>"
```

완료 후 이슈 URL을 알린다.

## 사용 예시

```
/issue-update
```
